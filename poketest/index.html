REFERENCE IMPLEMENTATION

How /poke loads its cards

01 · DATA

Prebuilt JSON catalog

./data/cards.json

/poke loads a catalog assembled ahead of time. The browser receives normalized, ready-to-use card records instead of requesting each expansion on every visit.

02 · ARTWORK

Separate image host

raw.githubusercontent.com/Vociferix/ptcgp-images/

Each card record contains an image filename. The app adds that filename to a fixed image base URL.

03 · DISPLAY

Same card tile structure

.card → .card-image → img

The test page reuses the /pokecards stylesheet's card classes, including the 3:4 image area and object-fit: contain, to make visual comparisons consistent.

What the test results tell us

List endpoints return brief records, not the full filter metadata. Individual card detail requests are needed for fields such as category, rarity, illustrator, and Pokédex ID. A promising path is to build a cached JSON catalog ahead of time, just as /poke does, but enrich each card from its detail endpoint and verify artwork URLs during the build.

TCGdex documents separate per-language card and set endpoints, brief list records, full individual-card records, and card image URLs. Card endpoint documentation · Set endpoint documentation.
